# 最小 Agent

这是任务 1 的作业：一个能自己调用工具、自己看结果、再决定下一步的小程序。

没有用任何 agent 框架，全部用 Python 自带的库写成，装好 Python 就能跑。

## 它能做什么

你给它一句话，比如"统计当前目录有多少个 py 文件"，它会自己决定先去列目录，拿到结果之后再回答你。

可用的工具一共 7 个：读文件、写文件、改文件、列目录、按名字找文件、按内容搜索、执行命令。任务只要求 3 个，我多做了几个。

## 怎么跑起来

先确认电脑上有 Python，在终端输入 python --version，能看到版本号就可以。

然后准备一个 DeepSeek 的 API Key，设置成环境变量，命令是 set DEEPSEEK_API_KEY=你的key，注意等号两边不要加空格。

接着就可以运行了。如果只想看看效果、不想花钱，直接双击文件夹里的 demo.bat，它会跑一遍离线演示，不联网也不消耗额度。

想真正用起来，就输入 python agent.py 加上你的任务。

## 它是怎么工作的

这部分是我这次学到最多的，也是最值得讲的。

先说一个反直觉的点：模型自己没有记忆。它不是记住了上一轮说过什么，而是每一轮我都把之前的对话重新发给它一遍。就像一个记性很差的人，每次开口前都得把前面的话重新讲给他听。

所以真正在干活的是外面这个循环，不是模型。

循环一共四步：

一、把目前的对话发给模型。
二、看模型有没有说"我要用某个工具"。
三、如果有，就在本地把那个工具跑一遍，把结果接在对话后面。
四、回到第一步，再发一次。

什么时候停？模型不再要求用工具的时候。它开始正常说话了，就说明它觉得信息够了，事情结束。

举个例子。我问它"统计当前目录有多少个 py 文件"。第一轮它没回答，而是说"我要用找文件的工具，条件是所有 py 文件"。我跑完工具，把结果接在后面，再发一次。第二轮它就说"有两个文件"，这次没有再要工具，于是结束。

一共就这一点东西。剩下的都是围绕这个循环做的工程细节。

## 我踩过的三个坑

第一个，我把工具返回的内容当成了列表。我的找文件工具返回的是一段文字，不是一串文件名。我在测试里按列表去遍历它，一直失败。后来才想明白：工具返回的内容是给模型看的文字，不是给程序用的数据。

第二个，我用 PowerShell 批量改代码，把文件改成了乱码。Windows 的 PowerShell 默认用一种中文编码读文件，而我的代码是另一种编码，一读一写全乱，连换行都没了，最后只能整篇重写。教训是：改代码用编辑器，别用命令行去替换文字。

第三个，模型说要调用工具的那条回复，必须原封不动地存起来。我一开始想"只存它说的话不就行了"，后来发现不行：下一轮发过去服务器会报错，因为后面那条工具结果找不到对应的那次调用。所以代码里就是原样保存，什么字段都不改。

前两个是我真踩过的，第三个是写之前就知道会出错、一开始就避开了，我如实说明。

## 目前的不足

执行命令没有任何安全拦截，文件操作有范围限制，但命令可以跑到任何地方去。

对话太长的时候，我只是把旧的内容折叠起来，没有真正做总结。

预算限制只能在下次请求之前生效，已经发出去的请求拦不住。

## 关于代码量

程序一共 810 行，看起来不少，但必需的部分大概只有 200 行：工具的注册、那个四步循环、以及每轮打印的过程。其余的都是加分项，比如并行调用、流式输出、子 agent 和预算控制。被问到的时候，我会按这个分层来讲。
